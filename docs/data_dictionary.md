# Data dictionary

All data is synthetic. Files live in `data/` and are regenerated by `python -m amlagent.data_gen`.

## customers.csv

| Field | Meaning |
|---|---|
| customer_id | `CUS-1xxxx` alerted customers, `CUS-9xxxx` network accounts outside the alert queue |
| customer_name, customer_type, occupation | KYC profile. Type is Individual or Business |
| expected_monthly_inflow_eur | Declared expected activity, used as the "normal" baseline |
| onboarding_date, signup_date | When the account was opened |
| residence_country, nationality | Nationality is present but deliberately **not** used as a risk indicator |
| customer_category | Customer or Merchant |
| business_type | For merchants: e.g. Food service, E-commerce, Logistics |
| date_of_birth | Individuals only (synthetic) |
| address | Fictional ("Example Street", "Sample Road"…) |
| risk_rating | Low / Medium / High |
| in_alert_queue | True for the 248 alerted customers |
| phone | From the reserved range +44 7700 900000–900999 |
| email | `@example.com/.org/.net` |
| signup_ip, signup_country, signup_device_id | Where and on what device the account was opened |
| home_city | Usual login location |
| account_status | ACTIVE, LIMITED or CLOSED |
| status_reason | Why an account was limited or closed, e.g. "Closed: money mule activity, SAR filed" |
| prior_sar | A SAR was previously filed on this account |
| status_typology | For actioned network accounts: the typology they were actioned for |

## transactions.csv

| Field | Meaning |
|---|---|
| txn_id | `TXN-1xxxxx` |
| timestamp, direction (IN/OUT), amount_eur | |
| channel | SEPA, WIRE, CARD, CASH_DEPOSIT |
| counterparty_name, counterparty_country, reference | Free text, as a real payment reference would be |

## logins.csv

| Field | Meaning |
|---|---|
| login_id | `LGN-xxxxxx` |
| timestamp | Login time |
| ip | From reserved ranges: 198.18.0.0/15 residential and office, 100.64.0.0/10 mobile carrier NAT, 203.0.113.0/24 public wi-fi, 192.0.2.0/24 hosting/VPN |
| ip_type | residential, mobile, public_wifi, hosting_vpn (as an IP-intelligence feed would label them) |
| city, country, latitude, longitude | Geolocation of the IP |
| device_id (DID) | Device fingerprint, stable across browsers and apps on one device |
| visitor_id (VID) | Browser or app cookie ID; can be cleared, and one device can have several |
| user_agent | OS and browser |
| success | False for a failed login |

## instruments.csv

| Field | Meaning |
|---|---|
| instrument_id | `FI-xxxxx` |
| type | bank_account or card |
| masked | Masked number as shown to an investigator |
| bank_country | Country of the bank |
| fingerprint | `BKF-...`, the same fingerprint on two accounts means the same underlying bank account or card |
| added_date | When it was added to this account |

## account_events.csv

| Field | Meaning |
|---|---|
| event_id | `EVT-xxxxx` |
| timestamp | When it happened |
| event_type | FINANCIAL_ADDED, FINANCIAL_REMOVED, PHONE_CHANGED, EMAIL_CHANGED, PASSWORD_RESET |
| details | e.g. "bank account LT** **** **** 4412 (LT) removed after withdrawals" |
| ip, device_id, country | Where the change was made from |

## disputes.csv

| Field | Meaning |
|---|---|
| dispute_id | `DSP-xxxxx` |
| txn_id | The disputed transaction on this account |
| opened, amount_eur | |
| reason | Unauthorised transaction, Scam: purchase / investment (APP), Item not received, Item not as described |
| status | Open; Lost by account holder; Resolved: seller won / refunded / withdrawn by payer |
| filed_by | payer (someone who sent money to this account) or buyer (a customer of a merchant) |

## alerts.csv, ground_truth.csv, sanctions_list.csv

`ground_truth.csv` holds the label, typology, scenario, difficulty variant and (v3) `expected_action`: NO_ACTION, REQUEST_DOCUMENTS, RESTRICT or CLOSE_ACCOUNT. It is hidden from the agents and used only for scoring.

## audit/reviews.jsonl (analyst decisions)

One line per decision: alert_id, reviewer, account_decision (CLOSE_ACCOUNT / RESTRICT / NO_ACTION / REQUEST_DOCUMENTS), sar_decision (FILE_SAR / NO_SAR), reason, and what the agent had recommended. The latest decision per alert is used for learning.

## Uploading your own data

Only `transactions.csv` is required (`txn_id, customer_id, timestamp, direction (IN/OUT), amount_eur, counterparty_name`). Every other file and column above is optional; missing ones get safe defaults, and missing alerts become one review case per customer. Download the template from the app's sidebar.

## Link strength (tools.py)

| Shared identifier | Strength |
|---|---|
| device_id, bank_fingerprint, phone, email | strong (medium if shared by more than 10 accounts) |
| visitor_id | medium (weak if shared by more than 10 accounts) |
| ip, residential, shared by ≤ 4 accounts | medium |
| any other ip | weak |
| anything shared by more than 25 accounts | suppressed (listed separately, not treated as a link) |
